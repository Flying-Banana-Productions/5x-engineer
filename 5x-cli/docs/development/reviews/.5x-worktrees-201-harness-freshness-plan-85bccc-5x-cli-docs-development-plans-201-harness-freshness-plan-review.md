# Review: Harness Asset Freshness Plan

**Scope:** `docs/development/plans/201-harness-freshness-plan.md` and referenced v2 design/current harness implementation.

## Summary

Direction, phasing, and test matrix are strong. Two correctness gaps make the plan not ready: normal non-force install can stamp stale skipped agents as fresh, and upgrade auto-sync contradicts the opt-in setting.

## Blocking issues

### 1. Non-force reinstall can create a false-fresh manifest

Phase 3 writes the current inputs plus hashes read from disk after `plugin.install()` (lines 593–595). Existing agent files are skipped without `force` (`src/harnesses/installer.ts:96–115`), while skills may update. Therefore, after changing a model and running ordinary `harness install`, the manifest records the *new* input fingerprint and the old agent bytes. Tier 1 then reports fresh, so hot-path warnings disappear despite stale baked agent frontmatter. Tier 2 is not run at fire points, and the migration/adoption guarantee is broken.

Specify a manifest-write policy that cannot establish a fresh baseline when any managed asset was skipped or differs from its current render. Preserve the old manifest (or record an explicitly unknown/stale state) until `sync` establishes an all-rendered baseline; add an integration test for model A → config B → non-force reinstall → Tier 1 remains stale/unknown → sync → fresh.

### 2. Upgrade auto-sync ignores `harness.autoSync = false`

Phase 7 step 3 says that with neither flag, upgrade auto-syncs whenever `losslessRefresh === true` **or** `harness.autoSync` is enabled (lines 1073–1077). The first condition makes auto-sync unconditional for every lossless project install; `autoSync` default false has no effect, contrary to the stated config contract and design requirement that it be opt-in.

Define the no-flag branch as report-only unless `harness.autoSync` is true and the lossless predicate passes. Keep `--sync` as the explicit override and `--no-sync` as report-only. Add a test proving a lossless stale install is not changed under the default configuration.
